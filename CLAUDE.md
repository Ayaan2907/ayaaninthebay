# ayaan-site — project context for coding agents

you are working on **ayaan-site**, my personal site: a terminal that answers as me, a canvas 3d map of sf, a `/build` command that ships small apps to puter, and a `/call` voice feature. repo: <https://github.com/Ayaan2907/ayaan-site>. live: <https://ayaan.sh>.

read `README.md` for the layout and `docs/architecture.md` before touching `api/` or `scripts/server.mjs`.

## stack (locked)

| layer | choice |
|---|---|
| front end | plain html, css, js. no framework, no bundler |
| server | node 22, `scripts/server.mjs`, `node:http`. vercel-style `(req, res)` handlers in `api/` |
| ai | puter sdk with my token, free models (`gpt-4.1` default). anthropic optional |
| content | `content/knowledge.js` and `content/voice.md` are the source of truth about me |
| tests | `node:test` in `tests/`, `scripts/check.mjs` as the lint |
| hosting | railway (railpack, `npm start`, healthcheck `/api/health`) |

adding a dependency needs an adr in `docs/adr/`. the site has one on purpose.

## conventions — non-negotiable

1. **no ai co-author trailer.** never `Co-Authored-By: Claude`, `Co-authored-by: Cursor`, `Claude-Session:` or any ai attribution on a commit, pr or issue. authorship is mine.
2. **conventional commits with a scope.** `feat(call): …`, `fix(map): …`, `docs(deploy): …`, `chore(ci): …`, `content(blog): …`, `refactor(server): …`, `test(env): …`. lowercase summary, imperative, under 72 chars. body explains why when the diff does not.
3. **small commits.** one concern each. stage files by name, never `git add -A` or `git add .`.
4. **`process.env` lives in `api/_env.js` only.** `console.*` lives in `api/_log.js` only. new env var → `_env.js` + `.env.example` + `docs/deploy.md`, or `npm run check` fails.
5. **validate at the boundary.** every handler parses and bounds its body before using it (length caps, allow-lists). never trust `req.body`.
6. **no secrets, no pii in the repo.** `.env.local` is gitignored; never read it into context. use `.env.example`. test data is obviously fake.
7. **voice.** lowercase, direct, no em dashes, no ai vocabulary (delve, robust, seamless, leverage, comprehensive, cutting-edge, empower, harness). applies to ui copy, commits, docs. `content/voice.md` is the spec.
8. **tests ride with behaviour changes.** a handler change gets a test in `tests/`. `npm run check && npm test` green before a pr.
9. **surgical changes.** do what the issue says. if you spot something else, say so in the pr, do not fix it in the same diff.
10. **the ai persona stays inside the fence.** it answers only from `knowledge.js`, declines family, employer internals, immigration, politics, religion. muvik is an apprenticeship, never employment. advanceiq is analytics for revenue-based finance, never "a lender". do not loosen `api/chat.js`'s hard rules.

## how to work here

- start: `npm ci && cp .env.example .env.local && npm run dev`. without a puter token the ai is offline and that is a supported state; test against it too.
- handlers hot-reload in dev (`NODE_ENV !== production` clears the require cache per request). the server itself restarts via `--watch`.
- `/build` runs in owner mode when `PUTER_AUTH_TOKEN` is set. builds publish to my puter account under `ayaan-builds/<slug>`. emergency stop: `BUILD_KILL=1` on railway.
- the map (`assets/city.js`) is a hand-rolled projection. data comes from `content/city.json` and `/api/github`; keep the renderer and the data separate.
- blog posts are generated by `.github/workflows/publish.yml` from `drafts/`. do not hand-edit `posts/index.json` or `feed.xml`.

## key files

- `api/_env.js` — every env var, validated. read this before adding config.
- `content/playbook.json` — the pipeline `/build` shows visitors. skill names and one-line descriptions from agentos are public; the full code-style and unslop rules are not, keep them prompt-side.
- `docs/build-playbook.md` — handoff notes for `/build`.
- `docs/deploy.md` — railway runbook, secrets, rotation, rollback.
- `docs/adr/` — why zero deps, why puter, why one server file.
